# Scotty v0.2.0 — Focus improvements and release-aware updates

This first published release establishes a versioned checkpoint for Scotty, the local web UI for Beads. It includes the existing board, list, epics, dependency graph, activity, and project-management features, plus the improvements below.

## What's new

- **Focus by assignee:** choose **Focus → Group by → Assignee** to see each person's work in its own row. Active people appear first; blank assignees remain distinct from a person named “Unassigned.”
- **Recently finished:** an optional completion column shows the latest seven finished tasks, with a clear count and access to the full set. Label lane filters apply before the limit. Active and blocked work remain uncapped.
- **Release-aware update notifications:** **Settings → Software updates → Stable releases** is the default. The sidebar shows the available version and links to its release notes. Checks work for Git checkouts, global copies, source downloads, and Docker installations. **Development (main)** remains available for Git checkouts.
- **Exact-version updates:** compatible, clean checkouts can install the release shown in the dialog. Newer work on main is not silently substituted. Local changes, feature branches, diverged history, changed release targets, and concurrent updates are guarded. Install/build failures can be retried.
- **Visible app version:** the sidebar displays the version of the running build, including installations without Git metadata.
- **Recent fixes:** dependency vulnerability updates, saved-theme hydration, clearer closed-item visibility in Epics, dependency search, and configurable minimal installation-usage reporting.

## Install this release

Prerequisites: a supported Node.js version (Node 20.9+; Node 22 or newer recommended), npm, and the Beads `bd` CLI for live project data. Without `bd`, Scotty can run with demo data.

```sh
git clone --branch v0.2.0 https://github.com/brendan-appstart/bead-me-up-scotty.git
cd bead-me-up-scotty
npm ci
npm run build
npm run serve
```

Open `http://localhost:3000`. This checks out the release tag; a detached checkout is expected and supported by the stable updater. The supervised launcher restarts automatically after a successful in-app update.

For a global `scotty` command, follow the README's `npm link` or global-copy instructions after building this release. This release does not publish a package to the npm registry or include a desktop installer.

## Update an existing installation

**Existing Git checkout:** existing versions may only know about main. To install this exact release, first commit or stash local source changes, then run from the app's checkout:

```sh
git fetch origin tag v0.2.0
git merge --ff-only 'v0.2.0^{commit}'
npm ci
npm run build
```

Restart Scotty. If Git refuses the fast-forward, preserve your work and use a separate release checkout rather than resetting your branch. Once on v0.2.0, later published versions appear through the stable update channel.

**Global copy or source download:** build a fresh checkout of the chosen release using the install steps, then repeat `npm install -g .` for a global copy, or replace the source installation. Restart Scotty. The in-app notice links to these instructions; it does not attempt a Git update in a non-Git installation.

**Docker:** rebuild the image from the release source and recreate the container using your existing configuration and persistent mounts. The in-app update notice is informational; update the image through your Docker workflow. See the README for container setup.

The update feature updates Scotty's source and dependencies, not your Beads issue database. Back up your local project data as usual.

## Controls and current limits

- **Settings → Software updates** controls checks and the Stable/Development channel per browser. Checks run on load and every five minutes, with shared server caching of release metadata. Disabling checks takes effect immediately. Release checks contact GitHub independently of the optional usage-statistics setting.
- Stable uses published GitHub releases, not the marketing site's deployment. Drafts and prereleases are excluded. Offline/API failures are handled quietly and preserve the last known notification.
- In-app source updates work on a clean `main` or detached checkout with forward history. They require the usual Node/npm build environment. Otherwise use the release instructions.
- `npm run serve` restarts automatically; other launch methods require a manual restart after rebuilding. Updates install only when requested.
- Focus remains optional; Board remains the default unless explicitly changed in Settings. Assignee grouping and Recently finished reset when leaving/reloading Focus.
- Validation covers a clean `npm ci` and standard production build, TypeScript/lint, synthetic browser scenarios, and disposable Git repositories. The dependency audit reported zero vulnerabilities. No user's installation was upgraded to test the updater.
- The build retains existing dynamic-filesystem tracing warnings in AI/showcase code; npm reports existing Recharts deprecation and local install-script approval notices. These did not prevent the clean install or build.
